Connect Keeper Commander

Keeper credentials remain in Keeper's private configuration.

1. Install Keeper Commander

The vault metadata helper requires a pip or pipx installation of Commander. Standalone bundled executables do not provide the Python environment it needs.

Linux or macOS

python3 -m venv ~/.boreal/keeper-env
~/.boreal/keeper-env/bin/python -m pip install keepercommander

Set Keeper Commander executable to ~/.boreal/keeper-env/bin/keeper, or your existing pipx-installed Keeper path.

Windows PowerShell

py -m venv "$env:LOCALAPPDATA\boreal\keeper-env"
& "$env:LOCALAPPDATA\boreal\keeper-env\Scripts\python.exe" -m pip install keepercommander

Set Keeper Commander executable to the full path of keeper-env\Scripts\keeper.exe in that environment.

Commander installation guide

2. Authenticate outside BOREAL

Open a terminal and start Keeper Commander using BOREAL's private config path. The file does not exist before the first session; Keeper Commander creates it as you configure and authenticate the session. BOREAL creates its parent directory when this Settings page opens.

Linux or macOS terminal 
"$HOME/.boreal/keeper-env/bin/keeper" --config "$HOME/.boreal/conf/keeper/config.json" shell
Windows PowerShell 
& "$env:LOCALAPPDATA\boreal\keeper-env\Scripts\keeper.exe" --config "$env:LOCALAPPDATA\boreal\conf\keeper\config.json" shell
Command using this computer's configured paths 
{{ keeper_setup_command }} --config {{ keeper_config_path }} shell
Sign in through Keeper Commander and complete your organization's MFA or SSO flow. Never enter your Keeper master password into BOREAL.

3. Register the device

In the Keeper shell, run this-device register. If your organization permits background access, run this-device persistent-login on. An authenticated shell alone does not establish that BOREAL can resume the session.

4. Verify access

In a separate terminal, use the same executable and --config path shown above, replacing shell with login-status. It must report Logged in. BOREAL must also run as the same OS user with access to Keeper's system keyring. If your organization's policy requires interactive authentication each time, unattended indexing cannot resume that session.

Close this assistant, enable Keeper, and select Save and test access. After validation, Keeper appears in navigation and as an optional metadata-update source.

Add GitHub resource owner

Step 1 of 4

Choose the Resource owner

A fine-grained token can access repositories for only one resource owner. Repeat this assistant for each personal account or organization you want BOREAL to inventory.

Enter the exact owner you will select on GitHub, such as uaf-acep. Adding this owner again replaces its stored token.

Select repository access and permission

  1. Select the intended Resource owner.
  2. Choose All repositories, or select only the repositories BOREAL should inventory.
  3. Under Repository permissions, set Metadata to Read-only.
  4. Leave all other repository, organization, and account permissions at No access.
BOREAL reads repository-level metadata only. It does not need Contents or any write permission.

Choose an expiration and generate the token

Recommended: choose a 90-day expiration, or the shortest period your organization can reliably renew. Short expirations reduce risk, but an expired token stops metadata updates until it is replaced.

Your organization may enforce a maximum lifetime or require administrator approval. BOREAL records the date as a reminder; GitHub controls and enforces expiration.

Open GitHub token generator

Store the generated token in BOREAL

Copy the token immediately after GitHub generates it, then paste it below. GitHub will not show it again.

BOREAL validates the token and repository listing, stores it only in its private local configuration, and never displays it again. An organization token may still require administrator approval before private repositories appear.
