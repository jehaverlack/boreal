3. Allow Commander to resume your login

At the authenticated Keeper vault prompt, run:

this-device register

If your organization permits persistent login (Stay Logged In), then run:

this-device persistent-login on

These are Commander commands, not commands for your normal terminal. A message that the device is already registered is fine. Persistent login lets Commander resume access for BOREAL's background updates; it does not guarantee that you will never need to sign in again.

4. Check access from a separate terminal

Leave the Keeper shell open. In a second terminal window, run the same startup command from step 2, changing only the final shell to login-status.

For an installation available as keeper on Linux or macOS:

keeper --config "$HOME/.boreal/conf/keeper/config.json" login-status

For the Windows PowerShell installation shown in Setup Keeper:

& "$env:LOCALAPPDATA\boreal\keeper-env\Scripts\keeper.exe" --config "$env:LOCALAPPDATA\boreal\conf\keeper\config.json" login-status

Use the same executable and configuration path as BOREAL, including any custom paths. The result should be Logged in. An authenticated shell or a browser signed into Keeper alone does not prove that a new process can resume access.

In BOREAL, open App → Settings → Keeper → Configure, enable Keeper, and select Save and test access. Once the test succeeds, use Update metadata → Keeper vault metadata.

Still not logged in, or access stopped working?
  • Repeat step 2 using BOREAL's configured executable and config path, complete SSO/MFA, and repeat the separate-terminal check. Restoring an older .boreal directory may restore an older configuration without a usable saved session.
  • Run BOREAL and Commander as the same operating-system user, with access to the same unlocked system keyring. A message such as Config stored in system keyring (Secret Service) means Commander uses protected system storage; the JSON file alone is not the complete login state.
  • If persistent login is blocked by your organization's policy, BOREAL cannot bypass it. Your Keeper administrator can confirm whether background access is allowed.
  • If login-status says Logged in but BOREAL's test fails, check the executable path in Configure Keeper and use the pip or pipx installation described in step 1.
