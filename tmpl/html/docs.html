Getting started

  1. Let BOREAL install and verify its private Rclone executable.
  2. Upload a Google OAuth Desktop app client JSON file. If you need to create one, open App → Create Google Client ID.
  3. Set up and authorize the read-only my-drive-ro remote.
  4. Use App → Settings for the service table. Choose Configure to enable a service, manage its connection and save its settings independently. Use Connections to repair a default Google connection or add another storage account.
  5. Persons is independent of Google Drive. Add entries manually or import a CSV; optionally link a Persons Google Sheet in App → Settings.
  6. Open Update and import the Google Drive metadata you want to explore.

Update the local metadata inventory

BOREAL searches its local SQLite inventory. Use Update to refresh that inventory from Google Drive.

  • Persons (~10 seconds) imports the configured directory spreadsheet.
  • My Drive (2–20 minutes) inventories content owned by or visible in My Drive.
  • Shared with me (2–20 minutes) inventories content shared with the authenticated account.
  • Shared Drives (1–6 hours) discovers and inventories accessible Shared Drives.
  • GitHub repositories inventories accessible organizations, owners, and repository metadata when the optional integration is enabled.
  • Keeper vault metadata inventories folders, record metadata, folder memberships and sharing information when Keeper Commander is configured.

Times are approximate and depend on inventory size, permissions, and network speed. You may close the update modal while a job runs; progress remains available from the Update control and status bar.

Optional GitHub and Keeper integrations

GitHub repositories

Enable the optional read-only integration under App → Settings. Use the token assistant to add one fine-grained GitHub token per resource owner, with repository Metadata: Read-only access.

  • Select GitHub repositories from the Update modal to refresh the local inventory.
  • Search by repository, description, topic, owner, organization, visibility, access, or tag.
  • Apply tags scoped to GitHub Repositories; tags remain local to BOREAL and never modify GitHub.
  • Repositories no longer returned by GitHub are retained as inaccessible historical records.

Keeper vault metadata

Install Keeper Commander and use the assistant under App → Settings to authenticate it with BOREAL's private Keeper configuration. Use a pip/pipx installation of keepercommander on Linux, macOS or Windows; the metadata helper needs Commander's Python environment.

  • Select Keeper vault metadata from Update to import regular and shared folders, record titles and types, modification dates, attachment counts and sizes, and folder-sharing information.
  • Open folders to browse their records, sort by column, and add or remove local tags on folders and records. Use Export Excel or Print to PDF to export the current folder or all-folder search with its filters and sorting. A record linked into multiple folders keeps the same tags everywhere. Permissions group users under each access label, with Persons identity pills for matching email addresses and aliases. User tags filter items by the tags on their sharing identities; click a user tag to include it, click again to exclude it, and a third time to clear it. Select multiple tags to require every condition (AND).
  • The helper emits only approved metadata. It excludes record fields, usernames, passwords, URLs, notes, custom-field values, TOTP seeds, keys and attachment contents.
  • Keeper manages authentication through its private configuration and system keyring. BOREAL needs a resumable session for background indexing.

Explore Drive content

Use My Drive, Shared Drives, and Shared with Me to browse the latest completed inventory.

  • Click a folder name to browse it inside BOREAL.
  • Click the Google Drive icon or a file name to open the item in Google Drive.
  • Use column fields to filter by name, type, size, date, owner, or permission.
  • Drag the right edge of a column header to adjust its width. Widths are remembered in this browser for each explorer, including after sorting, filtering, or changing tags. Use Reset widths above the table to restore the default layout. You can also Tab to a column edge and use Left/Right arrows; hold Shift for larger adjustments. Printed reports retain their default layout.
  • Click a hollow tag pill to require that tag. Click the solid pill again to exclude that tag; click the red “Not” pill to clear it.
  • Additional tags narrow results with AND: for example, Keep and Not Needs Review require Keep and exclude Needs Review. The same three-click cycle works for item and user tags in every explorer. The Any/All pill clears that tag group; Keeper calls its vault-tag reset Any Folder.
  • Use No tags to find records with no assigned tags.
  • Prefix an Owner value with ! to exclude matching owners.
  • Enable Include deleted items to see content retained from an older inventory but missing from the latest completed scan.

Filters combine: an item must satisfy the active column and tag filters. Use Clear filters to reset the view.

Choose sources to update

The Update dialog lists connected sources and remembers your last selection. On first use, select the sources you want; none are selected automatically. Google Resources are grouped together, and updating one Shared Drive by URL is available under its expandable option. Only requested sources appear in progress. After a failure, choose Acknowledge and choose sources to return to the main update dialog.

Google Groups

Enable Google Groups in App → Settings, then open Google → Groups and connect your Workspace account. The step-by-step Google setup guide in Settings walks through project selection, API enablement, Desktop OAuth credentials, and Workspace permissions. Enable the Admin SDK API in the same project as your Google Desktop Client ID, use an account with group-read privileges, and grant both read-only group and membership permissions. Groups uses a separate connection from Drive; your Drive authorization stays unchanged.

Select Google Groups and visible members in Update. Boreal imports groups you belong to, names, email addresses and aliases, descriptions, direct-member counts, and visible member identities, roles, types, and statuses. Open a group to browse its members; use Up or Base to return. Search, role filters, sorting, adjustable column widths, and matching Persons pills work in this viewer.

Restricted member lists are marked unavailable, not empty. Nested groups appear as members without recursively expanding them. Messages and conversation archives are not imported. Failed fetches retain the previous inventory, and snapshots are kept separately for each connected account.

Google reference: Groups API and member lists.

Classify content with tags

Tags are private BOREAL annotations. They do not change Google Drive labels, permissions, or files.

  1. Open App → Tags to add or edit a tag, description, color, and applicable Persons, Drive, GitHub, or Keeper scopes.
  2. In an explorer, select one or more rows. Select one row, then hold Shift while selecting another to select the entire visible range.
  3. Choose a tag and click Apply or Remove.
  4. Use colored tag pills above the explorer to filter the results.

Connect people and permissions

The Persons directory connects email addresses in Drive ownership and permissions to people, groups, service accounts, and organizations.

  • Add or edit an individual entry from Persons.
  • Download the CSV template and import a prepared directory file.
  • Link a Google Sheet under App → Settings and include Persons in a metadata update.
  • Apply person-only tags such as Data Loss Risk, then filter Drive owners and permissions by those tags.
  • Click an unknown identity badge in an explorer to begin adding it to Persons.

Export reports and download content

Excel reports

Apply explorer filters and click Export Excel. The workbook contains a Report Context sheet describing the filters and a Results sheet with clickable Google Drive links.

PDF reports

Apply explorer filters and click Print to PDF. BOREAL opens the complete filtered report in a new tab without the explorer's scrolling limits. Click Print / Save PDF and select your browser's PDF destination. The report requests landscape legal paper and retains clickable links.

Local downloads

Click the download icon beside an inventory item or accessible Shared Drive, choose a local destination folder, and start the copy. Downloads are retained in Migrations, can be resumed after interruption, and never delete the source. Use the Download status item to check the active copy.

Migrate Drive content

Select one or more active items in My Drive, Shared with me, or a Shared Drive, then click Migrate. The Migration Assistant records the source inventory and guides destination selection and copying. Shared Drive folders can be copied to another Shared Drive, a My Drive folder, or a local directory.

  1. Review the selected files, folders, and estimated size.
  2. Select a local folder, or paste and validate an allowed Google Drive destination folder URL.
  3. For a Google destination, add and authorize my-drive-rw from Remotes using an account that can write to that destination.
  4. Start the transfer. The first copy rejects destination name collisions; Resume / Synchronize updates missing or changed destination files while retaining destination-only files.
  5. Verify the completed content at the destination before taking any action on the source.
Safety boundary: BOREAL never deletes migration sources. A completed copy is not yet an automated checksum or permission verification; source removal remains a manual decision in Google Drive.

Upgrade BOREAL

BOREAL detects available releases but does not automatically replace the running executable.

  1. Open App → Update and click Check for updates.
  2. Download the binary for this system and verify it against the release SHA256SUMS.
  3. Finish active metadata updates, migrations, and downloads, then quit BOREAL.
  4. Make the new binary executable on Linux or macOS, if necessary, and start it. On Windows, close BOREAL before replacing or renaming the old executable.
  5. Return to App → Update to confirm the installed version.

Configuration, credentials, inventory, tags, migration history, and logs remain in the user-specific BOREAL home and are reused by the new executable. BOREAL applies required forward-only database migrations at startup.

For important inventories or annotations, back up the BOREAL home before a major upgrade. Keep the old executable temporarily if you want a rollback option, but do not replace a newer database with an older copy.

Application controls and safety

  • BOREAL remains available from its desktop tray or menu-bar icon when the browser tab is closed.
  • Use the desktop tray or menu-bar menu to reopen or quit BOREAL. Configured Google Drive, Rclone, GitHub, and Keeper destinations are available from icons in the WebUI navigation bar.
  • If BOREAL is already running, launching it again opens the existing WebUI instead of starting a second server.
  • You can also use App → Quit BOREAL or Ctrl-C in the terminal to stop the application gracefully. Interactive quit actions warn when active work would be interrupted.
  • Remotes shows BOREAL’s Rclone configuration status.
  • BOREAL binds only to the local computer and stores its database, configuration, credentials, and logs under the user-specific BOREAL directory.
  • Inventory operations use the read-only remote. Google migrations require the separate read/write remote; local tagging and reporting do not alter Google Drive content.
